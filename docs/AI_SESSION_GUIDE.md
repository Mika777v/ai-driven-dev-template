# AI_SESSION_GUIDE — セッションの始め方・終わり方・引き継ぎ

> **目的**: AI の会話（セッション）は長くなるほど、やりとりのたびに読み直す量が増え、前の内容も要約で薄れていく。**会話を短く区切り、続きは会話の外（`docs/PROGRESS.md` と Issue）からたどる**ための決まりをまとめる。どの AI ツールでも同じ考え方で使える。
> **いつ読むか**: セッションを始めるとき・終えるとき。会話が長くなってきたとき。別の AI ツールに作業を引き継ぐとき。
> **差し替え**: §1 の区切りの単位、§2 の読む順番、§6 の環境の準備をプロジェクトに合わせる。§7 は使うツールの行だけ残す。末尾の「記載例」は消してよい。

---

## 1. セッションの単位

- **区切り（{{CHECKPOINT_UNIT}}）ごとに、新しいセッションで始める。** 同じセッションで続けるのは、その区切りの中の作業だけ
- 区切りの中で次の Task に移るときは、会話を空にして（例: Claude Code の `/clear`）、次のセッションの最初の文（§5）を貼る。手元のファイル・依存・ブランチは残るので、準備をやり直さずに済む
- **新しいセッションにする**のは、区切りが終わったときと、**環境の設定（ネットワークの許可・環境変数・ツールの設定）を変えたとき**。設定はセッションを始めるときに読み込まれるため、会話を空にしても反映されない
- どちらの場合も、会話の続きは `docs/PROGRESS.md` からたどる

## 2. セッションの最初に読むもの（順番）

1. `AGENTS.md`（多くのツールは自動で読む）
2. `docs/PROGRESS.md` — 進み具合・次にやること・会話で決めたこと
3. 開いている Issue — 今の Epic とその Task
4. これから触る機能の `docs/AI_PROJECT_CONTEXT.md`（と要件の文書）の該当箇所
5. 触るコードとその周り

- **ファイル全体を読み込まず、必要な箇所だけを読む**（見出し・`grep`・行範囲を使う）
- {{EXTRA_READ}}

## 3. セッションの途中

- 会話が長くなったら、続きに要る内容を残して要約する（例: Claude Code の `/compact 開いている PR と次の作業を残す`）。関係ない作業に移るときは会話を空にする
- 確認のコマンドはまとめて1回で実行する
- ツールの出力は必要な行だけにする（ファイル全体・長いログを表示しない）
- CI・マージを待つときは、何度も見に行かず通知を待つ
- **会話の中で決めたことは、その場で文書に書く**（決めたことの置き場所は §4 の表）

## 4. セッションを終える前

`docs/PROGRESS.md` を更新して PR にする。決めたことは、種類に合わせて正本にも書く。

| 決めたことの種類 | 書く場所 |
|---|---|
| 進み具合・次にやること・開いている PR | `docs/PROGRESS.md` |
| 何を作るか・やらないこと | `docs/AI_PROJECT_CONTEXT.md`（人の確認が要る） |
| 後から変えにくい設計判断 | `docs/adr/`（人の確認が要る） |
| 作業・運用のルール | `AGENTS.md`・`docs/AI_*.md`（人の確認が要る） |
| つまずいた点と避け方 | `AGENTS.md` §6「気をつけること」 |
| 上のどれでもない小さな決めごと | `docs/PROGRESS.md`「会話で決めたこと」 |

## 5. 次のセッションの「最初の文」

区切りの報告（`AI_WORKFLOW.md` §6）の最後に、次のセッションでそのまま貼れる文を**コードブロックに1つだけ**書く。

形:

```
docs/PROGRESS.md の続きから。<区切りの名前>（Epic #<番号>）を #<Task番号> から始めて。
```

- 人が決めることが残っていれば、答えを書き込む場所も文の中に入れる（例: 「経路検索は〈A か B〉で進めて」）
- 別の AI ツールに引き継ぐときも同じ文が使える（読むものは全部リポジトリにあるため）

## 6. 新しいセッションの環境

新しいセッション（特にクラウドの作業環境）には、前のセッションの手元の状態が残っていない。

- 最初に: `{{INSTALL_COMMAND}}`
- 手元のデータ: {{LOCAL_DATA_SETUP}}（例: DB は起動時に自動で作られる / `make seed` で入れる）
- ネットワークの制限で外のサイトに届かないことがある。届かなかったことは「確かめられなかったこと」として報告し、`docs/PROGRESS.md` に残す

<summary>例: 個人開発（Claude Code のクラウドのセッション）</summary>

```markdown
## 1. セッションの単位
- **区切り（Epic 1つ）ごとに、新しいセッションで始める。**

## 6. 新しいセッションの環境
- 最初に: `npm install`
- 手元のデータ: DB は backend の起動時に自動で作られる
- 作業環境からは `api.example.com` が開けない（ネットワークで許可していない）。キーを使う確認は手元で行う
```

区切りの報告の最後:

```
docs/PROGRESS.md の続きから。E05 カレンダー入力（Epic #13）を #38 から始めて。
```

</details>

<details>
<summary>例: 複数のツールを使い分ける</summary>

```markdown
- 小さな修正・Issue 1件: Copilot coding agent に Issue を割り当てる
- 手元での読み書き: Cursor

どのツールも AGENTS.md → docs/PROGRESS.md の順に読むので、引き継ぎの文は共通。
```
