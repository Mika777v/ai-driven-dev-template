# TROUBLESHOOTING — 困ったときの手順書

> **目的**: エラーや想定外の動きが起きたときに、**症状 → 考えられる原因 → 見る場所・対処**を引けるようにする。人が困ったときにも、後から来た AI が不具合を調べるときにも、まずここを見る。
> **いつ読むか**: エラー・想定外の動きに出会ったとき。**いつ書くか**: 画面のメッセージ・API のエラー（ステータス）・起動のログを足す・変えるとき（同じ PR で直す）と、困ったことの原因が分かったとき。
> **差し替え**: 節（起動・画面・API など）はプロジェクトの作りに合わせて足す・消す。`{{...}}` を埋める。末尾の「記載例」は消してよい。
> **書き方のコツ**: 1行 = 1つの症状。「見る場所」には、そのメッセージや判定を書いているファイルを書く（コードを探す手間を省く）。

## 記載例

<details>
<summary>例: 経費精算アプリ（React + Express + SQLite）</summary>

```markdown
## まず見る場所
| `npm run dev` のターミナル | `[backend]` の行に backend の例外（500 のときは中身がここに出る） |
| 開発者ツールの「ネットワーク」で `/api/...` の行 | ステータス（400・404・500）と、応答の本文（`error`・`fieldErrors`） |

## 起動
| `ポート 3000 はほかのプログラムが使っています` と出て backend が終わる | 前に起動した backend が残っている | `lsof -i :3000` で探して止める。`backend/src/server.ts` |

## 画面に出るメッセージ
| サーバーに接続できません。backend が起動しているか確かめてください | backend が止まっている（Vite の proxy が 502 を返す） | ターミナルの `[backend]` を見る。文は `frontend/src/api-client.ts` |
| 入力に誤りがあります（＋欄の下に赤い文） | API の受け口のバリデーションで弾かれた（400） | 判定は `backend/src/validation/` |

## データ
| 追加の移動が消えた | 日次記録を消すと、追加の移動も一緒に消える（ON DELETE CASCADE） | 仕様どおり。`backend/src/db/migrations.ts` |

## 起きたことの記録
| 2026-11-04 | 画面が「エラーが起きました（HTTP 502）」だけを出した | backend が落ちていた | 502 のときは「サーバーに接続できません」と出すようにした（#93） |
```

</details>
