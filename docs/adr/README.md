# ADR（設計判断の記録）

後から変えにくい判断（データの置き場所・方式の選択・外部サービスの採用など）を、選択肢と理由と一緒に残す。
AI は「なぜこうなっているか」をコードから読み取れないため、ここが理由の正本になる。

- **書くとき**: 後から変えにくいことを決めたとき。迷わずに決めたことでも書く
  - 例: DB のテーブルの作り直し・データの移し方、データの置き場所、方式やライブラリ・外部サービスの選択、API の形、認証のやり方
  - PR の本文の「自分で決めたこと」に書くだけで済ませない（マージするとコミットのメッセージに埋もれる）
- ADR を追加・変更する PR は、自動マージせずに人が読んでからマージする（`docs/AI_WORKFLOW.md` §5）
- 新しく書くときは [`0000-template.md`](0000-template.md) をコピーする。ファイル名は `NNNN-内容.md`（連番）
- **一度決めた ADR は書き換えない。** 判断を変えるときは新しい番号の ADR を足し、古いほうの「状態」を「置き換え（ADR-NNNN）」にする
